title: Pipeline overview
description: An introduction to FuNPrep workflows and outputs.
---

FuNPrep is a modular pipeline for multimodal MRI preprocessing and
feature extraction. Its main entry point, `funp`, dispatches selected
processing modules and organizes outputs by subject and session.

## Processing modules

| Module | Command-line flag | Main processing scope |
| --- | --- | --- |
| Structural MRI | `-T1w_preproc` | T1w processing, segmentation, surface reconstruction, and fsLR resampling |
| Diffusion MRI | `-dwi_preproc` | Diffusion processing, diffusion metrics, tractography, and structural connectivity |
| Functional MRI | `-func_preproc` | fMRI processing, denoising, surface projection, and functional connectivity |
| Microstructure | `-micro_preproc` | Intracortical sampling, profile features, and microstructural profile covariance |

## How processing is organized

The main script reads command-line arguments and invokes the selected
modules in the following order:

1. Structural MRI
2. Diffusion MRI
3. Functional MRI
4. Microstructure

Selecting a downstream module does not automatically enable structural
processing. Anatomical outputs required by that workflow must already
exist or be generated by selecting structural processing in the same run.

## Input organization

Input paths use subject and optional session identifiers.

Provide identifiers without their prefixes: for example, use `01`
for a directory named `sub-01`.

Modality-specific filename options identify the portion of the filename
after the subject/session prefix and before the file extension.
Detailed examples will be provided in the input preparation guide.

## Output organization

Outputs are organized into modality-specific and shared directories.

| Directory | Purpose |
| --- | --- |
| `anat/` | Anatomical image outputs |
| `dwi/` | Diffusion image outputs |
| `func/` | Functional image outputs |
| `surf/` | Surface outputs |
| `parc/` | Parcellation outputs |
| `xfm/` | Spatial transformations |
| `features/` | Derived modality-specific features |
| `logs/` | Processing logs |
| `QC/` | Quality-control outputs where generated |

The files produced depend on the selected modules and processing options.
